# Передача и размещение лендинга Аэротона

25.11.2026. Код остаётся у Катерины: https://github.com/anisimovkat-hub/aerotone-landing . Клиент получает пакет для своего хостинга. Передача паролей и смена владельца GitHub не требуются.

## Что готово

- HTML/CSS/JS с локальными изображениями и шрифтами, относительные пути.
- Постоянный noindex на обеих страницах, robots.txt для чтения запрета, шаблоны X-Robots-Tag.
- Сборщик с явным списком публичных файлов, canonical/og:url выбранного адреса, ZIP, манифест версии и SHA-256.
- Две формы, обязательные email/телефон, проверка согласия, подтверждение успеха и callback цели после ответа приёмника.
- Адаптер amoCRM, образец переменных окружения, примеры Nginx/systemd. Реальные доступы и сервер не подключены.
- Проверки и сборка пакетов в GitHub Actions. Автодоставка на клиентский хостинг не подключена.

## Что запросить у клиента

1. Согласованный поддомен (предлагается b2b.aerotone.ru) и подтверждение, что имя не занято сервисом.
2. Действующие NS, доступ к DNS-зоне или контакт администратора. На 25.11.2026 WHOIS указывает RU-CENTER-RU, NS — ns1.reg.ru/ns2.reg.ru: это регистрация NIC.RU и DNS Рег.ру, а не доказательство хостинга.
3. Провайдер хостинга, панель, IPv4 или CNAME-цель нового сайта, поддержка HTTPS, тип веб-сервера.
4. Сервер в РФ с Python 3.9+ для адаптера либо согласованная интегратором замена. Статического хостинга для отправки в CRM недостаточно.
5. Аккаунт amoCRM, ID воронки/поля контекста, правила распределения и дублей, интегратор. Токен передать защищённо администратору сервера.
6. Утверждённое согласие и покрытие поддомена политикой, сроки хранения/логирования. Счётчик и выбор согласия на аналитику, если её включают.
7. Если нужна автодоставка — разрешённый SSH/SFTP/CI и ограниченная учётная запись. Ключи хранятся в защищённых CI secrets, не в исходниках.

## Состав пакета

- **public/** — только содержимое этой папки помещать в web-root нового поддомена.
- **backend/** — вне web-root, например /opt/aerotone/backend. Образец .env.example содержит пустые секреты.
- **nginx-landing.conf.example** — фрагмент для выделенного HTTPS server {} лендинга. Корневую папку и сертификат задаёт администратор; это не полный TLS-конфиг.
- **public/.htaccess** — X-Robots-Tag для Apache с mod_headers и разрешённым FileInfo. Сам Python и прокси этот файл не настраивает. На Apache отдельно настроить /api/leads через reverse proxy либо внешний HTTPS API.
- **aerotone-leads.service** — пример службы. Создать системного пользователя/группу aerotone. Реальные переменные — /etc/aerotone/lead.env, права 0600; SQLite — /var/lib/aerotone.
- **manifest.json** — версия исходников, адрес, статус подключения формы и SHA-256 файлов.

Архив Code → Download ZIP содержит все исходники разработчику; его нельзя целиком распаковать в web-root. Рабочие .env, базы и .git в публичный пакет не входят.

## Порядок установки

1. Сохранить DNS-зону и прежний релиз. Добавить отдельный сайт b2b.aerotone.ru и новую папку, например /var/www/aerotone/releases/<версия>. Основной сайт не перезаписывать.
2. Загрузить public, проверить ресурсы на техническом адресе. Для обновлений удобно переключать ссылку current после проверки новой папки.
3. В действующей DNS-зоне поменять только точную запись b2b на IP нового сайта либо CNAME провайдера. Не менять NS, @, www, ru, wildcard и почтовые записи. DNS указывает на сервер, а не ZIP/файл/URL с путём.
4. Выпустить сертификат, проверить HTTPS и автопродление, затем HTTP → HTTPS. X-Robots-Tag устанавливать только для виртуального хоста лендинга.
5. Установить backend вне web-root и переменные из образца. При другом адресе заменить ALLOWED_ORIGIN и LANDING_URL. LANDING_URL должен совпадать с page из формы, включая завершающий слеш. Дубли /index.html желательно перенаправлять на /, сохраняя query-параметры.
6. Настроить /api/leads → 127.0.0.1:8787, лимит тела 12 КБ, таймаут более 20 секунд. В Nginx перезаписывать X-Real-IP через $remote_addr. В приложении доверять только TRUSTED_PROXY_IPS. Порт 8787 не открывать извне. При CDN отдельно настроить доверенные real-IP на прокси; произвольному X-Forwarded-For не доверять.
7. Сначала протестировать адаптер и согласованную тестовую заявку в amoCRM, утвердить согласие. Затем собрать подключённый пакет с --endpoint /api/leads --forms-approved либо вручную поставить проверенный endpoint в публичном lead-config.js. Никогда не помещать туда токен. При изменении согласия одновременно обновить consentVersion в исходнике и CONSENT_VERSION на сервере.
8. Аналитику включать после реализации утверждённого выбора согласия. Текущий баннер — уведомление, счётчики не подключены. Callback window.aerotoneLeadConfirmed вызывается после подтверждённого приёма; контакты и ID заявки в цели не передаются.

Пока endpoint пустой, форма не передаёт заявки. До подтверждения интеграции не запускать рекламу с расчётом на формы. Текст согласия в privacy.html остаётся проектом до утверждения клиентом.

## Закрытие от органического поиска

В обеих HTML-страницах уже установлено:

```html
<meta name="robots" content="noindex, nofollow">
```

На хостинге дополнительно проверить заголовок:

```text
X-Robots-Tag: noindex, nofollow
```

GitHub Pages произвольные серверные заголовки этого проекта не устанавливает; для предпросмотра действует HTML noindex. На клиентском поддомене X-Robots-Tag для всего виртуального хоста также запрещает индексацию изображений и других ресурсов.

Robots.txt разрешает обход. Не ставить Disallow: / и не блокировать поисковых роботов авторизацией/WAF: иначе noindex не будет прочитан. В sitemap лендинг не добавлять. Основной сайт должен сохранить свои правила. При варианте страницы внутри Tilda закрыть именно страницу, а не весь проект.

Это указание поддерживающим его поисковикам, а не защита от доступа и не мгновенное удаление. Если URL уже в выдаче, клиент запрашивает удаление точных адресов в Search Console / Яндекс Вебмастере и сохраняет постоянный noindex. Не удалять из поиска весь домен компании. Реклама проходит отдельную модерацию.

Официальные правила: [Google](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [Яндекс](https://yandex.ru/support/webmaster/ru/controlling-robot/robots-txt).

## Проверки после установки

- HTTPS 200 на / и /privacy.html, без ошибки сертификата и переезда на GitHub Pages; ресурсы загружаются.
- В исходном HTML есть noindex; curl -I адреса страницы и изображения показывает X-Robots-Tag.
- /robots.txt доступен и позволяет прочитать запрет. Инструменты Google/Яндекса обнаруживают noindex.
- На телефоне и компьютере работают квиз, поля и согласие; пустые/некорректные контакты не отправляются.
- Тестовый лид появляется в нужной amoCRM один раз. Ошибка, таймаут и истёкший токен не дают ложной благодарности/цели.
- Backend, env и SQLite недоступны через веб. Главный сайт и почта работают как прежде.

## Обновления и откат

Правки делаем в GitHub. CI собирает пакет после изменений main; он намеренно отключён от CRM и не доставляется на клиентский хостинг автоматически. Для работающих форм администратор собирает релиз выбранного коммита с прежними согласованными --site-url, --endpoint и --forms-approved. Не затирать рабочий lead-config.js отключённой конфигурацией незаметно.

Секретный env и база хранятся вне папки релиза, не перезаписываются при обновлении. При изменении схемы базы заранее согласовать миграцию; этот релиз схему не меняет. При сбое вернуть прежнюю папку и публичную конфигурацию. DNS при необходимости восстановить из копии только для b2b. Удаление новой точной записи вернёт старое wildcard-поведение, включая прежнюю неготовность HTTPS, а не готовый старый лендинг.

Перед удалением хостинга сначала убрать DNS-привязку. Исходники откатывать revert-коммитом, без force-reset main.
